# 第2页

本章概述

在描述一个软件系统的时候，分析模型虽然有效地确定了将要构建的内容，但是却没有包含足够的信息来定义如何构建系统，设计模型可以用来填补分析和实现之间的差距。通常，分析过程就是调查问题，分析模型即对问题内容进行描述的模型，设计阶段就是在分析模型的基础上，找出解决方案，并建立设立模型。设计阶段的主要任务是通过定义一个合适的架构，用来描述系统各部分的结构、接口以及它们用于通信的机制。
本章将详细介绍系统设计的相关UML模型。

# 软件系统体系结构建模——包图

为了清晰、简洁地描述一个复杂的软件系统，通常都是把它分解成若干较小的系统（子系统）。如果需要的话，每个较小的系统还可以分解成更小的系统。这样，就形成了一个描述软件系统的结构层次。
在UML中，使用“包”代表子系统，使用包图描述软件的分层结构。

# 包拥有的元素

包拥有的元素：类、接口、组件、节点、协作、用例、图以及其他包。 
一个模型元素不能被一个以上的包所拥有。
如果包被撤销，其中的元素也要被撤销。 
一个包形成了一个命名空间。

# 包的名称

每个包必须有一个与其他包相区别的名称。
两种形式：简单名和路径名。

# 包对自身所包含的内部元素的可见性也有定义，使用关键字private、protected或public来表示。private定义的私有元素对包外部元素完全不可见；protected定义的被保护的元素只对那些与包含这些元素的包有泛化关系的包可见；public定义的公共元素对所有引入的包以及它们的后代都可见。

可见性

可见性的类型：
公有的（public） “＋”
受保护的（protected） “＃”
私有的（private）“－”

# 一、部署图的基本概念

部署图（Deployment Diagram）描述了一个系统运行时的硬件结点，以及在这些结点上运行的软件构件将在何处物理地运行，以及它们将如何彼此通信的静态视图。

# 一、部署图的基本概念

在一个部署图中，包含了两种基本的模型元素：节点（Node)和节点之间的连接（Connection）。在每一个模型中仅包含一个部署图。

# 节点是在运行时代表计算资源的物理元素。
节点的确定可以通过查看对实现系统有用的硬件资源来完成，需要从能力(如计算能力、内存大小等)和物理位置(要求在所有需要使用该系统的地理位置都可以访问该系统)两方面来考虑。

# 并发设计

在大多数系统中，尤其是联网的系统，会出现在同一时刻访问同一资源的情况，即并发操作。
如：汽车租赁系统、火车票销售系统等
因此，并发引入了下面的问题：

如何确保在他人访问之前，完全更新信息。例如，在添加新汽车型号的所有信息之前，必须阻止其他人访问这些信息。
如何确保信息在读取的同时不被更新。例如，在查看一个汽车型号的信息时，不要删除该汽车的型号。

# 并发设计

并发的简单方式：

系统规则——限制系统
业务规则——添加额外的业务规则

# 并发设计

系统规则：

在汽车租赁系统中，在顾客访问汽车目录时，当前访问的目录放在一个数据库中，该数据库是只读的；而在另一个独立的数据库中更新目录，每天切换一次数据库
这是对系统的人为限制

# 并发设计

业务规则：

两个顾客同时到不同的售票点买票，怎么办？
在售票的例子中，引入一个额外的业务规则：对于第一个对票务服务器访问的售票员，如果还有票，则临时对该售票员保留——即预订，该预订一直到售票员取消或者预订过期。

# 安全设计

如何确保信息安全是信息时代的一个新课题；需要从制度和技术等多方面进行管控。
安全的系统可以阻止有意或无意的误用。
系统的安全分为以下五个方面：

私密性：只有授权的人才能进行访问；
验证：需要知道信息的来源，以决定信息是否可信任；
不能反驳的信息：确保信息的初始提供者不能否认他们是信息的来源；
完整性：确保信息在传输过程中不受到破坏；
安全性：控制对资源的访问，安全性也称为授权。
