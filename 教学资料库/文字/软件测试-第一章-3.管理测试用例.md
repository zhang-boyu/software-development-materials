# 测试用例编写依据

一般说来，测试需求就是为了达到测试目标，项目中需要测试什么。测试过程中所有活动都可以追溯到测试需求。制定测试计划时，需要明确以下基本要素：明确测试需求（测试的目标内容）；测试方法；测试的进度安排；明确测试的环境是什么。其他因素：测试中需要的技能、工具以及相应的专业背景知识，测试中可能遇到的风险等。测试需求是测试计划的基础与重点。测试方案、用例、内容都要以测试需求为基础。  
测试用例的编写应该覆盖所有的测试需求，而测试需求是由软件需求转换而来，因此所有测试用例的执行结果最终都会追溯到软件需求，因此测试用例的编写依据主要是软件需求。此外，还应遵守相关的编写规则、规范等。

# 测试用例开发原则

测试用例编写的主要依据为项目提供的需求说明书和相关技术规范文档；

依据原则

对于需求说明书和相关技术规范中要求的主要功能点进行全覆盖测试，要求所有功能均能正常实现；

全覆盖原则

所有测试案例的编写要求规范，对于所有被测的功能点，应用程序均应该按照需求说明书和相关技术规范中的给定形式，在规定的边界值范围内使用相应的工具、资源和数据执行其功能；

规范原则

测试不仅仅针对系统功能特性进行测试，对系统的其他质量特性也进行全面的测试与评估。

# 如何写好测试用例

一个测试用例的完整与否决定了工程师在整个测试过程中是否可以有效顺利的完成任务，而能够创建一个高质量的测试用例也是我们每个测试人员的职责，由此，创建测试用例也成了测试员进入上任岗位之后的必修课。       
那么如何来建立一个完整健全的测试用例呢？这就需要有一个严格的程序与规范，下面就如何写好测试用例来做一下关键字段逐一说明。

# 如何写好测试用例

例如：涉及到具体功能的：Camera_ Color Mode；Camera_ Capture Mode.涉及到某个选项的：Camera_ Size of picture；Camera_ Mark and unmark image涉及到显示，路径：Camera_ Display of images；Camera_ Access to the Camera.涉及到菜单列表的：Camera_ Contextual menu after picture taken。

2.摘要

创建好标题后，摘要就需要对测试用例的标题展开描述，一般两到三句，主要描述测试用例需要验证软件的某个功能、选项、显示等问题，或是在不正当操作后软件不会发生异常现象。如果是协议方面的测试用例，则需写明验证的功能点。

# 如何写好测试用例

3.步骤

对测试用例操作步骤的具体描述，也是重点需要关注的地方，请尽量详尽。
此栏大致可以分为四个部分：
（1）前提条件（Pre-Condition）需注明在执行此条CASE前，需要做哪些前期准备。
（2）描述（Description）测试用例的测试步骤，需要在此详细描述，并以1.2.3.4.5.6….步分别写明。
    注意：
a. 测试步骤的颗粒度以模块的功能点为依据，能适应到其他类似项目。
b. 有些测试用例会分成很多的类型，比如基本测试用例（Basic Case),权限测试用例（Limitation Case），交互测试用例（Interaction Case）,压力测试用例（ intensive test case）等。

5.执行方式

执行方式有两方式，Manual代表此条测试用例需要工程师手动来操作执行，大多数的测试用例选择此项；Automated代表此测试用例是通过自动化来实现的，也就是通过一些脚本让手机自己来RUN，而工程师只负责去查看一下结果是通过（PASS）了还是失败（FAIL）了。

测试用例执行结果可以从覆盖率、执行率、通过率等几个方面进行分析和考察。测试用例覆盖率是指测试用例覆盖的功能与测试需求功能的比值；测试用例执行率是指已执行的测试用例数与测试用例总数的比值；测试用例通过率是指成功执行的测试用例数与测试用例总数的比值。 
测试用例的覆盖率需要达到100%；测试用例执行率是衡量测试效率的因素，一般说来，在测试完成时测试用例的执行率也需要达到100%；测试用例通过率是衡量用例本身设计质量和被测软件质量的因素。
